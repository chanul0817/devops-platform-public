# 01. Customer Problem

## 고객사 배경

고객사는 이미 애플리케이션을 보유한 소규모 개발 조직입니다. 서비스 기능 개발은 내부 개발팀이 담당하지만 배포, 모니터링, 로그 수집, 장애 대응은 담당자 경험에 의존하고 있습니다.

이 포트폴리오에서는 `app/`의 Spring Boot API를 고객사 애플리케이션의 샘플 artifact로 사용합니다. DevOps 컨설팅 범위는 애플리케이션 기능 개발이 아니라 운영 환경 구축입니다.

## 현재 문제

| Problem | Impact |
| --- | --- |
| SSH 접속 후 수동 배포 | 배포 시간이 길고 작업자 실수 가능성이 높음 |
| 배포 이력 관리 부족 | 어떤 버전이 운영 중인지 빠르게 확인하기 어려움 |
| 모니터링 부재 | CPU, JVM, HTTP 오류 상태를 사전에 알기 어려움 |
| 로그 분산 | 장애 발생 시 서버 내부 로그를 직접 확인해야 함 |
| 알림 부재 | 고객 문의 이후에 장애를 인지하는 경우 발생 |
| 대응 절차 미흡 | 담당자 부재 시 복구 시간이 길어짐 |
| 백업/복구 절차 부재 | 데이터 장애 발생 시 복구 기준이 불명확함 |
| 인수인계 자료 부족 | 구축 이후 고객사 운영자가 시스템을 이어받기 어려움 |

## 컨설팅 목표

- 반복 배포 작업을 자동화한다.
- 서비스 상태를 수치로 확인할 수 있게 한다.
- 로그를 중앙화해 장애 원인 분석 시간을 줄인다.
- 주요 장애 조건을 알림으로 연결한다.
- DB 백업과 복구 절차를 문서화한다.
- 운영자가 따라 할 수 있는 Runbook과 인수인계 문서를 제공한다.
